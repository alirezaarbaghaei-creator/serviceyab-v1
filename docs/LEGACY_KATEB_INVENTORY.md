# فهرست اولیه اجزای میراثی Kateb

این فهرست از درخت مخزن تهیه شده و هنوز جایگزین بررسی import graph و رفتار زمان اجرا نیست.

## حذف یا جایگزینی دامنه‌ای

- صفحات و اجزای نامه‌نگاری، ویرایشگر، پیش‌نمایش، قالب‌ها و تولید متن
- سرویس‌ها و storeهای letters، drafts، templates، AI writing و exportهای Word/PDF مرتبط
- سیستم اشتراک، سکه، پرداخت و اتصال اختصاصی Cafe Bazaar
- Edge Function با نام و منطق `kateb-api`
- migrationهای مربوط به نامه‌ها، قالب‌ها، پیش‌نویس‌ها، اشتراک و حساب سفارشی کاتب
- متون، تصاویر، آیکون‌ها، PWA metadata و تنظیمات برند کاتب

## نیازمند بررسی پیش از حذف

- `src/lib/api.ts` و لایه دسترسی داده: ممکن است مصرف‌کنندگان عمومی API در آن وجود داشته باشند.
- `src/store/authStore.ts` و صفحات پروفایل: منطق احراز هویت باید با مدل نقش‌های سرویس‌یاب جایگزین شود.
- `src/services/pushNotifications.ts` و افزونه‌های اعلان: ممکن است برای گردش کار خدمات مفید باشند.
- افزونه OTP و مجوزهای Android: باید پس از انتخاب روش احراز هویت تعیین تکلیف شوند.
- `android/` و تنظیمات Capacitor: اسکلت native قابل استفاده است، اما package id، نام، آیکون، مجوزها و فایل‌های build باید بازبینی شوند.
- `php-api/` و Supabase: باید یک مرجع Backend و مدل استقرار مشخص شود؛ دو مسیر موازی بدون قرارداد روشن نگه داشته نشوند.
- Workflowهای GitHub Actions: باید secrets اجباری شوند و هر fallback رمز/کلید حذف شود.

## هشدار امنیتی

در بررسی قبلی، migrationهای قدیمی شامل سیاست‌های RLS بسیار باز و مقادیر حساس/حساب پیش‌فرض بوده‌اند. این موارد نباید در محیط جدید فعال یا بازاستفاده شوند. هر Secret افشاشده باید خارج از GitHub نیز تعویض شود؛ حذف آن از commit جدید، تاریخچه Git را پاک نمی‌کند.

## خارج از دامنه پاک‌سازی کور

ابزارهای عمومی، تنظیمات build، فونت‌ها، تاریخ شمسی، کامپوننت‌های پایه، ساختار تست و قابلیت‌های native تا زمان اثبات عدم نیاز حذف نمی‌شوند.
