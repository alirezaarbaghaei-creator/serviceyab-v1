# مشخصات فنی فاز اول سرویس‌یاب

این سند ترجمه فنی پیوست شماره یک قرارداد است؛ هر قابلیت خارج از آن نیازمند توافق تغییر محدوده است.

## نقش‌ها

- **متقاضی:** ثبت‌نام/ورود، مشاهده و ویرایش اطلاعات مجاز پرونده، شرکت در آزمون فعال و مشاهده وضعیت درخواست.
- **مدیر اصلی:** مشاهده همه پرونده‌ها و نتایج، جست‌وجو و فیلتر، تغییر وضعیت اولیه، مدیریت سؤالات و تنظیمات آزمون، دریافت CSV.

در فاز اول نقش‌های متعدد مدیریتی و سطوح دسترسی سفارشی نداریم. حساب مدیر با درج نقش توسط مالک پروژه در دیتابیس مستقل ایجاد می‌شود؛ هیچ endpoint عمومی برای ارتقای نقش وجود ندارد.

## مدل داده

| جدول | هدف |
|---|---|
| `applicant_profiles` | اطلاعات فردی، تماس، شهر، تحصیلات، دوره‌ها، مهارت‌ها، سابقه، تجهیزات، توضیحات و وضعیت بررسی |
| `user_roles` | نقش مدیر اصلی |
| `exam_settings` | فعال‌بودن آزمون، مدت، تعداد سؤال، تعداد دفعات و سیاست نمایش نمره |
| `exam_questions` | متن سؤال، چهار گزینه و وضعیت فعال |
| `exam_answer_keys` | کلید پاسخ صحیح؛ جدا و غیرقابل مشاهده برای متقاضی |
| `exam_attempts` | زمان شروع/پایان، وضعیت و نمره |
| `exam_attempt_questions` | سؤالات انتخاب‌شده برای هر تلاش |
| `exam_answers` | پاسخ‌های متقاضی |

## آزمون و امنیت

- کلید پاسخ صحیح در جدول جداگانه نگهداری می‌شود.
- شروع آزمون و امتیازدهی در توابع دیتابیس انجام می‌شود؛ مرورگر کلید پاسخ را دریافت نمی‌کند.
- سؤال‌های آزمون از بین سؤالات فعال انتخاب می‌شوند.
- تعداد سؤال، مدت و تعداد دفعات مجاز از تنظیمات خوانده می‌شود.
- وضعیت آزمون و نمره در پرونده مدیریتی قابل مشاهده است.
- نمایش نمره به متقاضی تابع `show_score_to_applicant` است.
- آزمون ضدتقلب پیشرفته، نظارت تصویری و تحلیل آماری پیچیده جزو این فاز نیست.

## احراز هویت

پایه پیاده‌سازی Supabase Auth با شماره همراه و رمز عبور است. تأیید شماره همراه از مسیر OTP پیامکی Supabase انجام می‌شود؛ فعال‌سازی SMS provider، الگوی پیامک، اعتبار و هزینه آن باید توسط کارفرما تأمین/تأیید شود. قالب شماره همراه باید E.164 باشد؛ نمونه ایران: `+98912xxxxxxx`.

## نصب روی پروژه Supabase جدید

1. یک پروژه Supabase مستقل برای سرویس‌یاب بسازید؛ دیتابیس Kateb نباید استفاده شود.
2. migration `20261106090000_serviceyab_phase1_schema.sql` را در SQL Editor اجرا کنید.
3. Authentication > Providers > Phone را فعال و SMS provider را تنظیم کنید.
4. در تنظیمات URL، آدرس وب‌سایت سرویس‌یاب و redirect مجاز را وارد کنید.
5. مقدار URL و anon/publishable key را در محیط Build با نام‌های `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` تنظیم کنید. کلید service_role هرگز نباید در مرورگر یا مخزن قرار گیرد.
6. یک حساب مدیر را از طریق ثبت‌نام عادی ایجاد کنید. سپس UUID کاربر را از Authentication > Users بردارید و فقط مالک پروژه در SQL Editor اجرا کند:

```sql
insert into public.user_roles (user_id, role)
values ('UUID-OF-ADMIN-USER', 'admin')
on conflict do nothing;
```

7. مدیر می‌تواند تنظیمات آزمون را در جدول `exam_settings` مدیریت کند. آزمون به‌صورت پیش‌فرض غیرفعال است.
8. حداکثر ۵۰ سؤال و کلید پاسخ صحیح باید از محتوای تأییدشده کارفرما وارد شود.

## مواردی که هنوز برای تحویل باید تکمیل/آزمایش شوند

- رابط کامل مدیریت سؤال‌ها و تنظیمات آزمون
- مشاهده جزئیات کامل پرونده در پنل مدیر
- نمایش تایمر و مدیریت پایان زمان در رابط آزمون
- کنترل سقف ۵۰ سؤال در سطح دیتابیس
- تست end-to-end نقش متقاضی و مدیر با پروژه Supabase واقعی
- تست CSV با داده فارسی در Excel
- استقرار واقعی و آزمون معیارهای ماده ۱۳

این مخزن هنوز نسخه آماده تحویل قراردادی نیست.
