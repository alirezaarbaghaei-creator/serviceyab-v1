# نقشه راه تبدیل به سرویس‌یاب

مبنای این نقشه راه، پیوست شماره یک قرارداد فاز اول است. همه تغییرات روی شاخه `serviceyab-rebuild` انجام می‌شود و شاخه `main` دست‌نخورده می‌ماند.

## فاز صفر — تثبیت دامنه و ممیزی

- [x] ایجاد شاخه مستقل مهاجرت
- [x] دریافت و تثبیت محدوده فاز اول از پیوست قرارداد
- [x] ثبت مدل داده و سیاست‌های اولیه دسترسی
- [ ] ممیزی import graph و حذف وابستگی‌های غیرضروری
- [ ] تعیین روش ورود (شماره همراه و رمز عبور یا OTP) و تنظیم سرویس پیامک
- [ ] دریافت محتوای معرفی، پرسش‌های متداول، حداکثر ۵۰ سؤال و کلید پاسخ‌ها از کارفرما

## فاز یک — جداسازی Kateb

- جایگزینی برنامه فعلی با مسیرهای سرویس‌یاب
- حذف صفحات، کامپوننت‌ها، storeها و سرویس‌های نامه‌نگاری، تولید متن، قالب‌ها و آرشیو
- حذف امکانات اشتراک، سکه، پرداخت و اتصال Cafe Bazaar
- حذف API و Edge Function سفارشی Kateb
- کنارگذاری migrationهای قدیمی Kateb در شاخه مهاجرت و استفاده از پروژه دیتابیس مستقل
- حذف/بازنویسی متادیتا، برند، deep linkها و تنظیمات Android؛ اپلیکیشن native مستقل در فاز اول تحویل نمی‌شود

## فاز دو — هسته فاز اول

- احراز هویت و نقش متقاضی/مدیر
- پرونده متقاضی: اطلاعات فردی، تماس، شهر، تحصیلات، دوره‌ها، مهارت‌ها، سطح خوداظهاری، سابقه، تجهیزات و توضیحات
- بانک حداکثر ۵۰ سؤال چهارگزینه‌ای و تنظیمات آزمون
- اجرای آزمون، ثبت پاسخ‌ها، محاسبه نمره و ثبت سوابق
- وضعیت بررسی: جدید، در حال بررسی، تأیید اولیه، ردشده

## فاز سه — رابط‌های کاربری

- وب‌سایت عمومی و صفحات معرفی
- ثبت‌نام، ورود، پروفایل و پنل متقاضی
- آزمون و نمایش وضعیت/نتیجه بر اساس تنظیمات
- پنل مدیریت، داشبورد، جست‌وجو، فیلتر، پرونده و CSV

## فاز چهار — کیفیت و تحویل

- RLS مبتنی بر مالکیت و نقش؛ هیچ سیاست عمومی CRUD
- حفاظت از کلید پاسخ آزمون در سمت سرور
- محدودسازی تلاش‌های ورود/OTP و آزمون
- آزمایش سناریوهای معیار پذیرش ماده ۱۳
- استقرار روی زیرساخت توافق‌شده، راهنمای مختصر و آموزش مقدماتی

## معیار خروج

تمام معیارهای ماده ۱۳ پیوست قرارداد باید قابل آزمایش باشند. Build موفق به‌تنهایی معیار پذیرش، امنیت یا صحت گردش کار نیست.
